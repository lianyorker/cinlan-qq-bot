## 消息合并

- `QQ_GROUP_BATCH_WINDOW=3s`（默认 900ms 太短，秒级连发合不上）。
- `batch.go` debounce：同用户同群连发在窗口内合并为一条事件（`\n` 拼接），
  定时器随新消息重置；非群消息、不允许的群、`/` 前缀不合并。

## 回复节制（两层）

- **同文刷屏** `internal/bot/spam_repeat.go`：同一用户窗口内重复同文
  ≥`SPAM_REPEAT_COUNT`(3) 触发；`SPAM_REPEAT_MODE` 支持加权随机，
  当前 `ignore:60,hint:25,voice:15`（六成沉默装死）。好感度每个 streak
  只扣一次；hint 提示是"冷淡敷衍"而非骂人；`ignore`/`off` 直接丢。
- **@疲劳（mention fatigue）**：`noteReplySent` 记录群内连续回复同一
  用户的次数；连续 ≥`MENTION_FATIGUE_COUNT`(3) 后，该用户后续消息按
  `MENTION_FATIGUE_IGNORE_PCT`(65) 概率静默丢弃，
  `MENTION_FATIGUE_WINDOW`(10m) 过期清零；仅群聊、换人被回复自动重置。
  对付"换着文案追问同话题"的纠缠。env 均可调，COUNT=0 关闭。
- 私聊不套疲劳（唯一对话方不该被冷落）。

## 上下文断层修复（环境消息进历史）

- 之前 session 只记 `AddExchange`（回复过的对话），没回的群聊消息完全不进
  历史——别人在她答话间隙聊的梗她看不见，是"没上下文感"的主因。
- `internal/session/store.go` 新增 `AddObservation(key, userText)` 记单条
  user 消息；`AddExchange` 在尾条已是同文 user 时只补 assistant（去重）。
- `pipeline.go` `stageSession`（sessionID+promptText 就绪后）对每条到达消息
  调 `AddObservation`——attention 拒掉的闲聊也进历史。core 已同款镜像。

## 跨域隔离审计（2026-10-22 夜）

逐面核对"不同群的文档/文件交叉发"风险：

- **session**：按 `platform:self:X:group|private:chatID` 分 key，群聊观察只进本群历史 ✓
- **chatprefs/remember**：key=`chatType:chatID`，记住的内容不跨群 ✓
- **proactive**：取本群 session 历史做 opener，无跨群上下文 ✓
- **knowledge**：按绑定 `knowledge_bases` 过滤，cinlan/zkmall 隔离刻意保持 ✓
- **keyword 文件**：`kt.groups` 门禁 + 私聊群成员校验 ✓
- **filedelivery catalog**：security boundary 圈定 ✓

发现并已修的三个洞（`internal/tool/channelaction.go`，core 已镜像）：

1. **群主用不了**：`Actor.Role=SenderRole` 直通 QQ 角色，但只认 `admin`——
   `owner` 被挡。已修：`admin || owner` 同权。
2. **跨聊发送**：群管理员可对**任意群** `send_group_msg`/`upload_group_file`
   ——跨域文件/消息泄露口。已修 `crossChatTargetViolation`：`group_id` 必须
   等于当前聊天；`send_private*`/`upload_private*` 的 `user_id` 必须等于
   当前聊天；私聊语境带 `group_id` 直接拒。（`set_group_ban` 里的 `user_id`
   是被操作对象不是目的地，不动。）
3. **文件路径无约束**：`upload_group_file` 可传服务器任意路径（知识库、
   .env）进群。已修 `filePathViolation`：本地路径必须在 `BOT_ALLOWED_ROOT`
   内，http/base64 放行；`ChannelActionTool(platforms, cfg.BotAllowedRoot)`
   变参兼容旧签名。

遗留提示：`safeChannelActions` 只读白名单 + `send_like` 对全员开放；
写/管动作要求 admin/owner（= QQ 群管及以上）；跨域广播能力从工具层
已封死，需要时单独做 admin 工具。persona pack 的 `KnowledgeDir` 字段
已解析但未接 knowledgeStore——启用 packs 前按需接线。

## 矛盾回复修复（2026-10-23 凌晨）

线上案例：弱鱼发图→"@哈基咪 怎么回事"连续追问，七七先正确读出报错，
紧接着回"我看不到你图里写的啥"——同语境自相矛盾。两个根因：

1. **同聊天并发处理**：`runPlatformWorker` 每事件独立 goroutine，追问
   事件与上一事件并行跑，历史快照时上一回答还没 `recordExchange`——
   她看不到自己刚说过什么。已修 `chatLockFor`：`handlePlatformEvent`
   按 `chatType:chatID` 加锁串行，观察/回答顺序落盘。
2. **图只在当轮可见**：图片 attachment 只注入发图那轮的
   `request.Chain`；纯文字追问（"怎么回事"）只留 `[图片]` 占位符，
   模型答"看不到"。已修 `noteRecentImage`/`recentImageFor`：每聊天
   内存缓存最新图（3 分钟窗口），无图追问且文本短（≤14 字）或命中
   指代词（图/截图/报错/上面/刚才/看看…）时重新挂图。

3. **引用消息正文不进 prompt**：`QuotedChain` 只贡献了图和文件，
   被回复消息的**文本**从未注入——"回复那条说啥意思"是盲答。已修
   `stageAgent`：quoted 非空时把其 `PlainText`（截 300 字）以
   `（引用：…）` 前缀并进 `request.Text`。

附带修：环境观察跳过命令消息（`commandMessage`）——`/status` 这类
操作指令不算"她听到的闲聊"，denied 命令不再残留历史。相关过期测试
断言已同步（历史现在含当轮观察消息；发送失败保留 user 观察、只丢
assistant 行）。core 已同构镜像。

4. **裸情绪标签漏字面量**：模型实际发 `[亲亲]`/`[委屈]`/`[傲娇]` 这种
   无前缀标签，而 `faceMarkerPattern` 只认 `[face:名]`/`[表情:名]`——
   全部漏成字面文本。已修 `expandBareEmotionTags`（`reply_plan.go`）：
   裸标签先展开——名字在 `faceNameToID`（含新别名 生气/脸红/开心/哭…）
   的转成真 QQ 表情，`emotionToEmoji` 表（傲娇/星星眼/撒娇/装死等无
   QQ id 的）降级成 unicode emoji；`[face:未知名]` 分支同样走 emoji
   兜底而非静默丢弃。`parseFaceMarkers` 的 found 语义修正：纯 emoji
   展开也算"有变更"，否则展开结果被丢弃。

残余提示：小文本附件内容同样只在当轮内联（`chainFileText`），追问
"那个文件写了啥"不会重读——文件消息低频，暂不补，需要时照
`recentImage` 同款加个 recentFile 缓存即可。

### 回复一大坨+一直换行（2026-10-23 上午）

现象：女友人设回复变成一整条多行长文，不像真人发短气泡。

1. **根因是配置不是代码**：服务器 `.env` 里 `QQ_MAX_REPLY_CHUNKS=1`
   把回复拆分整体关掉，`[[NEXT]]` 和空行分段全退化成换行塞进一条
   气泡。已改回 `4`。
2. **延迟按打字长度算**：`replyPartDelay` 原来拿**上一条**的长度且
   只加 8ms/字；改为按**将发的这条**的长度 +30ms/字（封顶 80 字，
   ~2.75s）——一条长段明显"打更久"，符合真人气泡节奏。
   `typingDelay`（首条 1.2s+55ms/字 上限8s）原有不动。core 镜像。
3. 备注：ambient observation 会让历史更密、回复略显话密，属预期
   取舍；若仍嫌啰嗦可在人设侧压长度，不建议砍观察。

### 模型把每条消息看成两遍（2026-10-23 晚）

现象：群聊私聊都出现"text+text"复读观感——七七以为用户的话自身
重复拼接，实际是**模型侧重复**而非接入层。

根因：`stageSession` 上游把当轮消息 `AddObservation` 记入会话
（这是 ambient 上下文的设计），但 `SnapshotState` 取历史时这行
观察坐在 `request.History` 末尾，而 `request.Text` 又带同一句话
→ 模型看到的输入= 历史末行+Text 两次。`AddExchange` 的落库去重
帮不上——请求构造时重复就已存在。

修法：取快照后若历史末行 `role==user && content==promptText`
就剥掉一条（store 里保留，只不喂给当轮模型）。三条测试断言同步
改回"请求历史不含当轮、会话存储仍含"。已上线，core 镜像。
