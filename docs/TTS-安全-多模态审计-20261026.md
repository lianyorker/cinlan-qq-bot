## 一、TTS / 唱歌 / 语音

### 引擎矩阵（5 种后端）

| 引擎 | 配置 | 格式 | 音色 | 多语言 | 免费 | 特殊能力 |
|------|------|------|------|--------|------|---------|
| **Edge**(默认) | `VOICE_MODE=edge` | mp3 | zh-CN-XiaoyiNeural 等 SSML 声库 | ⚠️需换 voice name | ✅ | clause-level prosody jitter 降低单调感 |
| **OpenAI** | `VOICE_MODE=openai` + API_URL | mp3 | nova 等 | ✅原生 | ❌ | 兼容任何 OpenAI-shape 代理 |
| **Volcano/豆包** | `VOICE_MODE=volcano` + VOLC_TOKEN | mp3 | seed-tts-2.0 | ✅自动语种识别 | ❌ | NDJSON 流式;支持 Emotion 参数 |
| **Breeze Blue** | `VOICE_MODE=breeze` + API_KEY | mp3 | voice_id 克隆声 | ✅ | ❌ | 唱歌 singProvider 专线 |
| **Command** | `VOICE_MODE=command` + COMMAND | 由命令定 | 由命令定 | N/A | 看命令 | shell 逃生舱 |

### 唱歌 [[SING]] 链路
- **专用引擎**：singProvider 独立于 voiceProvider(voice.go:410),persona `(sings)` tag 走 Breeze 克隆声
- **降级链**：singProvider → voiceProvider 普通声 → 退化文字
- **安全**：双层——`voiceObviousEroticPattern` 正则硬拦(19 词) + `voiceClipSafe` LLM 二次审
- **限制**：≤200 rune/clip,最多 2 clip,per-chat 45s 冷却,全局日 quota
- **无节拍/音高控制**：TTS 直接念歌词,无旋律对齐(技术限制非代码缺口)

### ASR 语音识别
- 引擎：OpenAI 兼容 `/audio/transcriptions`（SiliconFlow SenseVoiceSmall 免费）
- 链路：收到语音 → 下载(≤8MB) → 转写 → 注入消息文本
- 失败：返回 error,退化为 `[语音]` 占位;无重试

### [[VOICE]] 完整链路
```
模型输出含 [[VOICE]]…[[/VOICE]]
  → extractVoiceMarkers: 分离文字 + clips
  → sanitizeVoiceClip: 去舞台指示/元说明
  → prosodyNormalizeVoiceClip: 去 URL/markdown/emoji
  → deliverVoiceClips:
      → VoiceEnabled / SingEnabled per-chat 开关检查
      → voiceBudget per-chat 45s 冷却
      → personaVoice: persona 配置的 voice/rate
      → sendVoiceClips:
          → voiceMaxRunes 截断
          → voiceClipSafe 色情检查
          → provider.Synthesize → mp3
          → 失败: retry 默认voice → singProvider fallback → 退化文字
          → 构造 record 段 → sender.Send
```

### TTS 缺口

| 优先级 | 缺口 | 说明 |
|--------|------|------|
| 🔴 | **无 TTS 缓存** | 同一句话每次重新合成,浪费 API quota+延迟。思路:短文本 hash→磁盘缓存,命中直接发 |
| 🟡 | **语音语速不随 mood 自动调** | 真人心情差语速慢、好了语速快。当前 rate 是 persona 静态固定,不受 mood 影响。思路:personaVoice 函数根据 mood score 微调 rate |
| 🟡 | **voiceClipSafe LLM 挂时默认放行** | 设计意图"宁放不冤",但 LLM 不可用期间只靠 19 词正则拦色情语音 |
| 🟡 | **Edge TTS 无跨引擎自动降级** | edge 挂了(403/封 IP)不会自动切 openai,只 retry 同引擎 3 次 |
| 🟡 | **无全局 TTS 并发限制** | 多条消息同时触发 → 并行 N 个 HTTP 到同一 API,可能触发 rate limit 批量失败 |
| 🟢 | **Edge 中文 voice 说英文带口音** | 无自动检测文本语言→切 voice 的逻辑;Volcano/OpenAI/Breeze 原生支持多语言 |
| 🟢 | **voiceQuota 额度用完无提示** | 语音静默不发,用户不知道为什么 |
| 🟢 | **ASR 无重试** | 单次失败直接放弃 |

| 🔴 | **出站无违禁词硬拦截** | 模型被诱导输出政治/色情/暴力→直接发群→平台封号 | 加出站关键词正则硬拦截,命中替换通用拒绝语 |

## 六、与前几轮审计的关系

本轮覆盖的是前几轮**明确未涉及**的三个面:

| 前轮 | 本轮补充 |
|------|---------|
| 记忆/向量优化(v1-v3) | → TTS 缓存建议(同思路:热路径去 IO) |
| 拟人化审计(a0-a9) | → 语音情绪映射(拟人深度补丁) |
| 拟人化全面审计(QQ能力/token/深度) | → 消息安全是全新维度;多模态收发是能力面补全 |

**安全面是本轮最大增量**——出站无违禁词、记忆投毒、未识别标记泄漏三个问题在前几轮完全未触及,但风险最高(直接关系平台封号和人格劫持)。建议优先于功能优化处理。
