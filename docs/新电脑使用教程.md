# 一、获取程序（两种方式）

**方式 A：拿发布包（推荐，新电脑无需开发环境）**

在开发机上打包：

```powershell
.\scripts\package-release.ps1 -Version 0.2.0
```

生成 `dist/` 下的 Windows x64 压缩包（含 Go bot + QQNT loader + hook + runtime）和 SHA-256 校验文件。拷贝压缩包到新电脑解压即可。

**方式 B：新电脑上从源码构建**

新电脑需要安装 Go、Rust、Node.js、PowerShell，然后：

```powershell
git clone <仓库地址>
cd cinlan-qq-bot
.\scripts\build.ps1
```

# 二、新电脑必备条件

- **Windows 10/11 x64**（native 模式仅支持此平台）
- **已安装官方 QQNT 版 QQ** 并登录过一次（loader 附加到官方 QQ，不改写 QQ 文件）

# 三、配置 `.env`

```powershell
Copy-Item .env.example .env
notepad .env
```

必改项：

```dotenv
QQ_PLATFORM=native
# 你的群号白名单（逗号分隔多个）
QQ_GROUP_ALLOWLIST=123456789
# 私聊白名单，留空=禁用私聊
QQ_PRIVATE_ALLOWLIST=987654321

# AI 接口（二选一）
AGENT_API_MODE=openai
AGENT_API_URL=https://api.example.com/v1/chat/completions
AGENT_API_KEY=<你的key，建议放用户环境变量>
AGENT_MODEL=<模型名>

# 管理接口令牌，务必改成强随机值
ADMIN_API_TOKEN=<强随机token>
```

**`SESSION_ENCRYPTION_KEY` 必须设置**（会话库是 AES-256-GCM 加密的 SQLite）。生成一个随机 32 字节 base64 key，放到**用户环境变量**里，不要写进 `.env`：

```powershell
# 生成一次
[Convert]::ToBase64String((1..32 | %{Get-Random -SetSeed $_ }) -as [byte[]])
[Environment]::SetEnvironmentVariable("SESSION_ENCRYPTION_KEY", "<生成的key>", "User")
```

# 四、人格定义（`data/personas.json`）

默认路径就是 `data/personas.json`（`PERSONAS_FILE` 可改）。把 [examples/personas.json](cci:7://file:///D:/Company/cinlan/apps/cinlan-qq-bot/examples/personas.json:0:0-0:0) 复制过去改：

```powershell
Copy-Item examples/personas.json data/personas.json
```

结构（[examples/personas.json](cci:7://file:///D:/Company/cinlan/apps/cinlan-qq-bot/examples/personas.json:0:0-0:0) 有完整示例）：

- **`default_persona`**：没被 Binding 指定时用谁
- **`routing_scope`**：决定 bot 什么时候开口（`include_topics` 该管的 / `exclude_topics` 必须写，如闲聊、拉票 / 正反例句）
- **`system_prompt`**：正式回答的人格，骨架见 `docs/人格模板.md`
- **`begin_dialogs`**：2-3 个真实工作样例，别写寒暄
- **`custom_error_message`**：工具失败时的话术，附 `/人工` 逃生口

# 五、Binding 关联映射（`data/chat-bindings.json`）

这是「哪个群/私聊 → 用哪套人格/Provider/工具」的映射：

```powershell
Copy-Item examples/chat-bindings.json data/chat-bindings.json
```

```json
{
  "bindings": [
    {
      "name": "support-groups",
      "platform": "*",
      "chat_type": "group",
      "chat_ids": ["123456789"],
      "persona": "human-support",        // 关联上面的人格 name
      "provider": "customer-api",        // 可选，关联 providers.json
      "tools": ["capture_webpage"],      // 可选，授权的工具
      "knowledge_bases": ["support"],    // 可选，授权的知识库
      "reply_policy": { "mode": "ai_decide", "confidence_threshold": 0.72 },
      "learning_enabled": true
    }
  ]
}
```

未命中任何 Binding 的群/用户会被直接忽略（fail-closed）。

### 不用 @，让 bot 自己判断是否回复

Binding 里的 `reply_policy` 会完全覆盖全局 `QQ_REQUIRE_MENTION`，所以 `.env` 不用改：

```json
"reply_policy": {
  "mode": "ai_decide",
  "on_error": "mention_only",
  "confidence_threshold": 0.72,
  "history": { "mode": "none" }
}
```

- `ai_decide`：白名单群里的每条消息先发给轻量路由模型，按人格的 `routing_scope` 判断该不该回，置信度达标才正式回答，`@` 与否不再重要
- `always`：群里每条消息都直接进 AI 回答，最耗 token，慎用
- `on_error`：路由失败或低置信度时的兜底，`mention_only` 表示只有 `@` 才回（推荐），`ignore` 表示沉默
- 路由有独立预算：`BOT_ATTENTION_RATE_LIMIT` / `BOT_ATTENTION_RATE_WINDOW`（默认同一人 1 分钟 20 次）
- `routing_scope.exclude_topics` 务必写清楚（闲聊、拉票、表情包刷屏），否则容易被无关消息唤醒
- 私聊白名单内本来就不需要 `@`

# 六、文件上传/交付（`FILE_CATALOG_PATH`）

模型不能自选本地路径，只能发**管理员登记过的文件**。配置：

```dotenv
FILE_CATALOG_PATH=data/file-catalog.json
FILE_DELIVERY_MAX_BYTES=104857600
```

```powershell
Copy-Item examples/file-catalog.json data/file-catalog.json
```

每个条目：`id`（模型引用用）、`aliases`（别名）、`path`（真实文件位置，必须在 `BOT_ALLOWED_ROOT` 内）、`private_only`（仅私聊可发）、`allowed_group_ids`。用户私聊索要时，模型调用 `deliver_file` 自动发送。

**引导用户加好友 + 自动同意**（文件只能发给好友，所以要先自动通过好友申请）：

```dotenv
# 仅 OneBot 兼容模式（QQ_PLATFORM=onebot）生效；native 模式暂不支持
ONEBOT_AUTO_ACCEPT_FRIEND=true
```

开启后，收到好友申请会自动同意并写日志 `auto-accepted friend request`。流程：引导用户私聊/添加机器人为好友 → 自动通过 → 用户私聊索要文件 → `deliver_file` 发送。

# 七、可选功能

# 八、启动与验证

```powershell
# 双击 start.cmd，或：
cmd.exe /k powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

它会启动 Go runtime → 自动拉起官方 QQ → 弹出正常登录窗口 → 你登录 QQ。验证：

```powershell

```

`readyz` 返回 200 后，在白名单群里 `@机器人 你好` 测试。

# 九、OneBot 兼容模式（可选，替代 native）

OneBot 模式下 Cinlan 连接外部 NapCat 服务，支持自动同意好友、群管理、多账号等 native 暂不支持的能力。

1. 部署 NapCat 并在它的 WebUI（默认 `6099` 端口）登录 QQ。
2. NapCat 启用 WebSocket Server（如端口 `3001`），设置 access token。
3. `.env` 改为：

```dotenv
QQ_PLATFORM=onebot
ONEBOT_TRANSPORT=forward_ws
ONEBOT_WS_URL=ws://127.0.0.1:3001
ONEBOT_ACCESS_TOKEN=<和 NapCat 一致的 token>
ONEBOT_AUTO_ACCEPT_FRIEND=true
```

4. 重启生效。白名单、人格、Binding、文件目录等配置两种模式通用；但会话历史按平台前缀（`qq-native:` / `qq-onebot:`）隔离，切换后历史不互通。

## QQ 平台与连接

| 配置 | 默认 | 含义 |
|---|---|---|
| `QQ_PLATFORM` | Windows 下 `native`，其他系统 `onebot` | 运行模式：native 直连官方 QQNT；onebot 连接外部 NapCat |
| `QQ_GROUP_ALLOWLIST` | 无 | 群白名单，逗号分隔群号；`*` 表示所有已加入的群 |
| `QQ_PRIVATE_ALLOWLIST` | 空 | 私聊白名单，逗号分隔 QQ 号；留空=禁用私聊 |
| `QQ_REQUIRE_MENTION` | `true` | 群聊是否必须 `@` 才回；Binding 的 `reply_policy` 可覆盖 |
| `QQ_QUOTE_REPLY` | `true` | 回复时引用原消息 |
| `QQ_GROUP_AT_SENDER` | `true` | 群回复时 `@` 提问者 |
| `QQ_MAX_REPLY_RUNES` | `1500` | 单条回复最大字符数 |
| `QQ_MAX_REPLY_CHUNKS` | `4` | 回复最多分成几条消息发送 |
| `QQ_GROUP_BATCH_WINDOW` | `900ms` | 群消息合并窗口，窗口内的连续提问合并处理 |

# 十一、常见问题

- **`readyz` 返回 503**：看日志里的 `wrapper_loaded`、`session_attached` 和 `state` 字段定位；native 模式下 QQ 更新后需按 `原生运行时.md` 重新验证签名。
- **机器人不回群消息**：检查群号是否在 `QQ_GROUP_ALLOWLIST`、是否命中 Binding、`reply_policy` 模式和置信度阈值。
- **私聊文件发不出去**：确认双方已是好友（可开 `ONEBOT_AUTO_ACCEPT_FRIEND`）、文件在 `FILE_CATALOG_PATH` 登记过且路径在 `BOT_ALLOWED_ROOT` 内、大小未超 `FILE_DELIVERY_MAX_BYTES`。
- **回复内容"失忆"**：检查 `SESSION_TTL` 是否过短、`SESSION_ENCRYPTION_KEY` 是否每次一致（key 变了旧库读不出）。
- **转人工**：群聊 `@机器人 /人工`，私聊 `/人工`；恢复用 `/恢复`。
