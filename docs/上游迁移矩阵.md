# 上游功能迁移矩阵

本文档记录 Cinlan 对 NapCatQQ 和 AstrBot 的 clean-room 功能对照。只参考公开协议、文档和可观察行为，不复制受限实现代码。

默认主链不运行 NapCatQQ 或 AstrBot。官方 QQNT 负责账号登录和 QQ 协议，Cinlan 自有 loader/runtime 只附加到官方会话；OneBot transport 是显式开启的兼容模式。

## 运行时分层

```text
QQ runtime
  -> Platform Adapter
  -> Unified MessageChain
  -> Ordered Pipeline
  -> Command / Plugin / Agent
  -> Provider / Tool / Knowledge
  -> Persistence
  -> Admin API
```

## Native QQNT 运行时

```text
Official QQNT
  -> cinlan-qq-loader.exe
  -> cinlan-qq-hook.dll
  -> runtime/qqnt/runtime.cjs
  <-> QQNT IPC v1
  -> cinlan-qq-bot.exe
```

`Source` 表示本地源码是否实现并接线。`Evidence` 表示验证强度，分三档：

- `unit`：单元测试覆盖，但对手方是模拟 runtime 或 fixture 安装目录，不接触真实 QQ。
- `syntax`：只做过语法检查，没有行为测试。
- `live-runtime`：真实 QQNT 已启动并附加 wrapper/session，但未发送测试消息。
- `not verified`：没有针对真实 QQNT 的运行验证。

当前已完成真实 QQNT 的启动、wrapper/session attach 和 ready 验证，但尚未完成
真实消息的 `event -> Agent -> sendMsg` 端到端验证。`internal/platform/qqnt/adapter_test.go`
仍使用本地 TCP fixture 验证协议边界，不能替代真实消息测试。

## NapCat / OneBot 兼容

常用客服动作已提供 typed wrapper：

- `send_group_msg`、`send_private_msg`、`delete_msg`
- `get_login_info`、`get_group_info`、`get_group_member_info`
- `get_group_list`、`get_friend_list`、`get_msg`
- `set_group_ban`、`set_group_whole_ban`、`set_group_kick`
- 文本/图片/语音/文件 message segment

其余动作可以通过 `onebot.Client.CallAction` 发送，仍由统一的 token、`echo`、超时和错误处理保护。

| NapCat 功能组 | Cinlan 状态 |
|---|---|
| 消息事件和群回复 | Native 和 OneBot 均已实现 |
| Notice/request/meta 事件 | OneBot 保留原始字段；native v1 待做 |
| HTTP/SSE/forward/reverse WebSocket | `forward_ws`、`reverse_ws`、`http_sse`、`reverse_http` 已实现并测试 |
| 多账号路由 | Account registry、name/`self_id` 路由和状态 API 已实现 |
| 群管理和查询 | 常用 typed wrappers 已实现；其余动作通过鉴权的通用 action API 发送 |
| 富媒体 / Highway / FFmpeg | Chain 和引用保留；上传/转码待做 |
| 进程守护 / QQNT 启动附加 | Cinlan native loader/hook 已实现；登录 UI 仍是官方 QQ |
| 网络/插件 WebUI | 仅 JSON admin API；WebUI 不在范围 |
| Guild/新 API 和 packet/OIDB 扩展 | 待做；需要独立协议工作或授权 |

## 交付批次

1. **运行时基础**：platform/message/pipeline、OneBot action 边界、持久化会话。**已交付。**
2. **客服平台**：provider registry、RAG、handoff、command/plugin hooks、鉴权 admin API。**已作为首个可用切片交付。**
3. **扩展运行时**：tool loop、MCP Streamable HTTP transport、动态插件、skills、subagents、流式。**Tool loop、MCP HTTP、skills 和同步 subagent 切片已交付；其余待做。**
4. **多模态与运维**：富媒体上传、STT/TTS、备份、追踪、多账号。**持久化 Cron 和多账号路由已交付；其余待做。**
5. **运行时独立**：自有 loader/hook、QQNT runtime、鉴权 IPC 和 native adapter。**Native v1 已交付；富媒体和管理动作仍待做。**

每个后续功能必须同时补齐入站事件、领域模型、持久化、出站动作、API 契约、测试和文档，不能只添加一个未接线的类型或接口。
