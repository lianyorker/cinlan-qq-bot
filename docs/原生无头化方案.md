# Native 无头化全功能方案（对标 NapCat 功能面）

> 本文档是交给执行者（人或 AI）的完整任务书。目标：`QQ_PLATFORM=native` 在无桌面
> 环境下完整可用，功能面对标 NapCat 公开文档，clean-room 实现，不部署 NapCat/OneBot。

## 零、背景

本仓库已实现自有 QQNT native 运行时：

- `runtime/loader`（Rust）：cinlan-qq-loader.exe 挂起启动 QQ.exe + cinlan-qq-hook.dll
  patch 启动保护/IAT/文件重定向，不改写官方文件
- `runtime/qqnt/runtime.cjs`：附加官方 QQNT wrapper/session，通过鉴权 NDJSON IPC
  （token 握手、loopback、帧上限、action correlation）与 Go 通信
- `internal/platform/qqnt/adapter.go`：Go 侧 adapter，已有群/私聊文本收发、
  引用、私聊文件、本地图片、AVSDK 只读监听

当前缺口：依赖官方 QQ 桌面窗口登录、无头不可用、协议面只覆盖消息子集。

## 一、硬性约束（每个阶段都适用）

1. **Clean-room**：禁止复制/反编译 NapCat、LLOneBot 等受限实现；只参考公开协议
   文档和可观察行为。方法见 `docs/上游迁移矩阵.md`。
2. **不修改官方 QQ 安装文件**：官方 `package.json`、`wrapper.node`、`QQNT.dll`
   hash 不得变化；延续 hook/内存 patch 方式。
3. **IPC 安全不回退**：token 握手、loopback-only、帧上限、超时全部保留；新增
   envelope/action 采用增量方式，不破坏 v1。
4. **失败显式**：签名/patch/登录/调用失败必须写 `runtime_status.last_error`，
   禁止 fallback 静默隐藏。
5. **每项功能必须同时补齐**：runtime.cjs 探测/监听、IPC 契约、Go adapter 转换、
   配置项、平台 Event/Outbound 或 action、测试、文档。禁止只加未接线的类型。
6. **版本敏感**：每个阶段完成后按 `docs/原生运行时.md` 的「更新验证」记录
   QQNT 版本基线（hook SHA256、冷启动时长、ready 状态）。

## 二、能力清单（对标 NapCat 公开功能面）

按依赖和风险分五波实现。每波独立可验收，顺序不可调换（后面的依赖前面的）。

### 第一波：事件面补齐（不依赖无头，最先做）

| 能力 | 说明 | 实现要点 |
|---|---|---|
| 好友申请事件 + 同意/拒绝 | `request/friend` | 新 IPC 事件 `friend_request`（uin/uid/flag/comment/昵称）+ action `approve_friend`；配置 `QQNT_AUTO_ACCEPT_FRIEND` 自动同意；参照 av_event 独立通道模式 |
| 入群申请事件 + 审批 | `request/group` | 新 IPC 事件 `group_request` + action `approve_group`（含 invite 子类型） |
| 消息撤回通知 | `notice/group_recall`、`friend_recall` | 新 IPC 事件类型，Go 侧转平台 notice 事件；可选择联动会话存储删除 |
| 戳一戳 | `notice/notify/poke` | 同上 |
| 群成员变动 | increase/decrease | 同上；供后续群欢迎/离开逻辑使用 |
| 群禁言/群管理通知 | ban/notice 类 | 同上 |
| 好友/群列表缓存 | get_friend_list / get_group_list | runtime.cjs 内缓存 + IPC action 查询，供 Go 侧白名单和 Binding 匹配使用 |

### 第二波：发送面补齐

| 能力 | 说明 | 实现要点 |
|---|---|---|
| 群文件上传 | 群聊 send file | 现有私聊文件路径扩展到群（群文件系统或普通 element，探测后择优） |
| 语音发送 | 语音消息 | 需要格式探测（silk/AMR），先支持本地文件路径 |
| 视频发送 | 视频消息 | 同上 |
| 闪照 | 短时效图片 | 探测 picElement 的闪照字段 |
| 合并转发 | node/forward 消息 | 探测 QQNT forward 服务；先做「构造转发」再做「解析收到的转发」（收侧已有 multi-forward 转文本基础） |
| @全体成员 | at all | at element 扩展 |
| 表情回应 | 消息表情回应 | 探测对应 NTService 方法 |

### 第三波：查询面补齐

| 能力 | 说明 |
|---|---|
| 历史消息 | 群/好友漫游历史（分页），供会话恢复和审计 |
| 转发消息解析 | get_forward_msg 等价 |
| 群信息/群成员列表 | 完整成员列表（现有 get_group_member_info 是单查） |
| 群文件系统 | 列表/下载链接 |
| 账号信息 | get_login_info、资料读写 |

### 第四波：无头化（依赖第一~三波的事件面，否则无头没有意义）

1. **窗口抑制**：`runtime/loader` hook 拦截 QQNT 主窗口创建/显示
   （CreateWindowExW/ShowWindow 路径），进程和消息循环保持正常。
   配置 `QQNT_HEADLESS`（默认 false）；关闭时行为与现状完全一致。
2. **无 UI 登录**：
   - 本地会话有效 → 直接 quick login（已有基础）
   - 需要扫码 → runtime.cjs 取协议层二维码经 IPC 回传，Admin API 新增
     `GET /api/v1/login/qr`（PNG/base64 + 状态 + 刷新），
     `GET /api/v1/login/status`；登录成功推进到 ready
3. **无头守护**：进程崩溃/登录态过期时的重启与重新登录策略（结合 systemd/服务化）。

### 第五波：高级能力（可选，按需排期）

- Markdown 消息与按钮（QQ 官方机器人接口形态，探测 QQNT 支持度）
- 自定义 OIDB/packet 通道（风险最高，最后做）
- 群精华、群签到、点赞、戳一戳主动发送
- 多账号 native attach（多 QQ 号同机）

## 三、验收标准（每波都要过）

1. 全量 `go test ./...`、Rust 测试、`node --check` 通过。
2. 新增事件在真实 QQNT 上收到并正确转换（记录到
   `notes/qqnt_runtime_analysis.md`，标注 QQNT 版本）。
3. 新增 action 在真实 QQNT 上调用成功且失败路径有 last_error。
4. 官方 QQ 文件 hash 前后对比无变化。
5. 无头相关：`QQNT_HEADLESS=true` 无窗口出现；浏览器扫码登录成功；
   `/readyz` 200；消息闭环可用；`QQNT_HEADLESS=false` 回归一致。
