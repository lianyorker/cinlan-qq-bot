# 亲密度系统

## 设计目标

让 persona 对"和对方有多熟"有真实的感知：聊得越多关系越近，白名单内的人直接视为最亲近。分数跟着人走（`selfID:userID`），群里积累的好感在私聊里同样生效。

## 档位与计分

| 档位 | 原始分 | 含义 |
|---|---|---|
| 陌生 | 0-4 | 刚认识，礼貌保持距离 |
| 认识 | 5-19 | 聊过几次，可以放松 |
| 熟悉 | 20-59 | 熟人，主动关心 |
| 亲近 | 60-149 | 很熟，撒娇玩笑都可以 |
| 亲密 | 150+ | 最亲近的人，亲昵称呼放开 |

- **默认增长**：每次成功完成一轮对话 `+1`（`recordExchange` 内计入）。
- **AI 自评**：模型可在回复末尾追加 `[[AFFINITY:+N]]` / `[[AFFINITY:-N]]`（N 取 1-5），由它自己判断对方温柔有趣加分还是冒犯骚扰扣分。标记在发送前剥除，对方看不到。
- **白名单顶格**：私聊（过了 `QQ_PRIVATE_ALLOWLIST`）、群主、管理员、binding `allowed_users` 一律按 `亲密（100/100）` 注入，不走计分。

## 展示

- Prompt 注入：`对方和你的亲密度：XX（NN/100）。<档位行为提示>`，并交代"对方问起就照实答"，所以用户自然语言问"我们亲密度多少"也能得到数值回答。
- 命令：`/亲密度`（别名 `/affinity`）随时可查，`/帮助` 列表已收录。

## 持久化

`data/affinity.json`，环境变量 `AFFINITY_FILE` 可改路径。文件不存在时从零开始；损坏会告警但不影响启动。

## persona 分档提示（`affinity_prompts`）

`personas.json` 里每个 persona 可以按档位定义专属行为提示，key 用档位名：

```json
{
  "name": "毒舌女仆",
  "affinity_prompts": {
    "陌生": "对不熟的人照例毒舌嘲讽，但别太过分，毕竟还不熟。",
    "认识": "有点眼熟了，毒舌照旧但可以带点熟人间的调侃。",
    "熟悉": "老熟人了，骂归骂，可以透出一点其实挺关心他的意思。",
    "亲近": "嘴上嫌弃心里在意，毒舌里掺点别扭的温柔。",
    "亲密": "对最熟的人可以毒舌里带明晃晃的偏爱，偶尔会补一句关心。"
  }
}
```

未配置 `affinity_prompts` 的 persona 自动回退到内置通用提示（`affinity.GenericHint`）。
