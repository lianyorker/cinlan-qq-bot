# 自定义扩展

## 选择扩展方式

| 方式 | 适合场景 | 是否可按 Binding 限制 |
|---|---|---|
| providers.json | 多个 Custom/OpenAI-compatible Provider | Provider 和 reply policy 可按 Binding 选择 |
| plugins.json | HTTP webhook、before/after/event hook | 当前 webhook/plugin 注册是进程级，不能按 Binding 授权 |
| MCP_SERVERS_FILE | 远程工具服务 | Server 可按 Binding 授权；工具子集仍由服务发现结果决定 |
| SKILLS_DIR | 可读的领域说明和流程 | Skill 可按 Binding 授权 |
| SUBAGENTS_FILE | 同步 handoff 专家 | 当前由全局 tool registry 注册；Provider 可单独选择 |
| Go registry | 本地业务逻辑、数据库或受控平台动作 | Tool/Persona/Provider 可通过现有 Binding 资源边界接入 |

## Go 扩展

公开源码中的 cmd/cinlan-qq-bot/local_extensions.go 是一个空的构建入口。
在不提交业务代码的本地树中，新增同名函数文件并使用 localbusiness build tag：

```go
//go:build localbusiness

package main

func registerLocalExtensions(ctx context.Context, cfg config.Config, service *bot.Service, logger *slog.Logger) error {
    return registerOrderTool(ctx, cfg, service, logger)
}
```

实际注册时使用 service.ToolRegistry()、service.PersonaRegistry()、
service.ProviderRegistry() 或 service.PluginRegistry()。扩展应通过依赖注入获得
受控的业务服务，不应读取 Token、执行任意 shell、拼接未校验路径或直接代理任意 URL。

构建示例：

```powershell
$env:GO_BUILD_TAGS = "localbusiness"
.\scripts\build.ps1
```

Linux/macOS 的本地扩展必须保持 Go 端可移植；不要在共享包中引用 Windows-only loader
或 QQNT 注入 API。Windows native 的 loader/hook 仍只在 Windows x64 生成。

## 按群或个人配置自主回复

先在 personas.json 为每个角色填写 routing_scope，再在
chat-bindings.json 的 reply_policy 选择：

- disabled：当前 Binding 不进入回答链。
- mention_only：群聊只处理直接 @；私聊不建议使用此模式。
- always：命中白名单后直接回答，适合明确的一对一服务。
- ai_decide：先运行无 Tool 的 Attention 路由器，再决定是否正式回答；群聊和私聊都支持。

ai_decide 默认不向路由 Provider 发送历史、QQ 标识、昵称、原始消息 ID 或完整回答
提示词。路由失败和低置信度默认忽略；需要时可配置 on_error=mention_only，让群内
直接 @ 在路由器故障时继续回答。路由调用受 BOT_ATTENTION_TIMEOUT、
BOT_ATTENTION_RATE_LIMIT 和 BOT_ATTENTION_RATE_WINDOW 独立限制。

## 生命周期和授权边界

- Tool、Skill、Knowledge 和 MCP 资源在模型请求和执行时都要经过 Binding 快照校验。
- Persona、回答 Provider 和 AI 路由 Provider 可由 Binding 指定；Session override 只覆盖
允许覆盖的 Persona/Provider 设置。
- Command 和 Plugin 当前是进程级扩展，命中白名单后的所有 Binding 都可能看到它们；若需要
细粒度授权，应把逻辑实现为带 Binding 检查的 Tool，或先在扩展内部校验 scope.binding_name。
- Subagent 默认不继承主会话历史；只有显式 inherit_history=true 才复制最近消息，且跨
Provider 前必须确认数据驻留和脱敏边界。
- 动态 Admin API 可管理配置，但生产 UI 应使用专用脱敏 DTO，不要把完整 prompt、路径、
session scope 或凭据返回给浏览器。

## 测试要求

每个扩展至少覆盖空输入、超时、重复事件、权限失败、未命中 Binding、外部服务失败和
敏感字段不外发。跨平台扩展至少运行：

```text
go test ./...
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build ./cmd/cinlan-qq-bot
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build ./cmd/cinlan-qq-bot
```

最后两条中的 GOOS/GOARCH 是目标环境变量；在 PowerShell 中应逐项设置 $env:GOOS
和 $env:GOARCH，不要把 Windows native 组件打进 Linux 包。
